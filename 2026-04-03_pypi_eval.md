# PyPI Readiness Evaluation

Review date: April 3, 2026. Scope: architecture, API surface, usability, invariants, packaging, docs, CI, and release engineering. Validation performed: repo inspection, full test suite, `mypy processbehavior`, `ruff check .`, and runtime spot checks in the project virtualenv.

1. `P0` Stratified helper API is internally inconsistent. [`AnalysisResult.strata`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L370), [`focus()`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L414), [`get_stratified_charts()`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L651), [`get_stratified_chart()`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L680), and [`list_strata()`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L730) do not share one contract; in runtime, `result.strata` works while `list_strata()` returns `[]` and `get_stratified_charts()` returns `{}` for the same stratified result. Why it matters: any user building dashboards or drill-down tools on stratified analyses will hit broken behavior immediately. Cleanest minimal fix: make `strata` the single source of truth, rewrite all helper methods to operate from the stored `'strata'` list plus `metadata['stratify_col']`, and stop inferring anything from chart names.

2. `P0` The README is not publishable in its current state. [`README.md`](/Users/nicholas/Documents/projects/processbehavior/README.md#L13) uses an obsolete API, and the file literally contains draft/LLM scaffolding text at [`README.md:41`](/Users/nicholas/Documents/projects/processbehavior/README.md#L41). Why it matters: the PyPI landing page is the package for most users; a broken README kills trust faster than almost anything else. Cleanest minimal fix: replace the README with one tested quickstart built around `ProcessBehavior(...).formulate(...).execute()` and remove all editorial scaffolding.

3. `P0` Installation docs advertise extras that do not exist. [`docs/getting-started/installation.md:24-34`](/Users/nicholas/Documents/projects/processbehavior/docs/getting-started/installation.md#L24) and [`docs/intro.md:127-130`](/Users/nicholas/Documents/projects/processbehavior/docs/intro.md#L127) tell users to install `processbehavior[plotting]` and `processbehavior[excel]`, but [`pyproject.toml`](/Users/nicholas/Documents/projects/processbehavior/pyproject.toml#L21) only defines `images` and `dev`. Why it matters: installation commands copied from docs will fail on day one. Cleanest minimal fix: either add real `plotting`/`excel` extras or remove those commands and document the actual dependency model.

4. `P0` The publicly exported `Analysis` API is effectively a trap. It is exported from [`processbehavior/__init__.py`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/__init__.py#L44), showcased in the README, but its actual constructor is [`Analysis(spec, request, ...)`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis.py#L115), not `Analysis(df, spec)`. Direct use currently falls into a raw `AttributeError`. Why it matters: you are shipping a broken top-level API surface. Cleanest minimal fix: either remove `Analysis` from the root namespace and docs for `0.1.0`, or add a supported compatibility constructor/factory that matches the documented pattern.

5. `P1` The exception model still leaks raw `ValueError` from public-facing paths. There are remaining `raise ValueError` calls in [`study.py`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/study.py), [`analysis.py`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis.py#L149), and [`FocusedAnalysisResult.focus()`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L1615). Why it matters: callers cannot reliably catch `ProcessBehaviorError` for all user errors. Cleanest minimal fix: convert every user-triggerable validation/configuration failure to `ValidationError` or `ChartNotAvailableError`.

6. `P1` CI does not verify that the package can actually be published. [`.github/workflows/ci.yml`](/Users/nicholas/Documents/projects/processbehavior/.github/workflows/ci.yml#L1) runs lint, mypy, and tests, but no `python -m build` and no `twine check`. Why it matters: a green repo can still fail at the packaging step. Cleanest minimal fix: add a release job that builds sdist/wheel and runs `twine check` on both artifacts.

7. `P1` PyPI metadata is incomplete. [`pyproject.toml`](/Users/nicholas/Documents/projects/processbehavior/pyproject.toml#L5) has no classifiers and no `project.urls`. Why it matters: discoverability, trust, and compatibility signals are weak on PyPI. Cleanest minimal fix: add Python version classifiers, license/topic classifiers, and URLs for homepage/docs/issues/source.

8. `P1` The docs still contradict the runtime entrypoint naming. [`docs/reference/api.md:25-28`](/Users/nicholas/Documents/projects/processbehavior/docs/reference/api.md#L25) documents `.columns`, but runtime exposes `.cols` in [`ProcessBehavior`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/process_behavior.py#L437). Why it matters: copy-paste usage fails and the API looks unstable. Cleanest minimal fix: standardize docs on `.cols`; only keep `.columns` if intentionally added as an alias.

9. `P1` The README promises a result shape that no longer matches the library. [`README.md:34-39`](/Users/nicholas/Documents/projects/processbehavior/README.md#L34) references `result.points`, `subgroups`, `limits`, and `overall`, but the current object is [`AnalysisResult`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L133) with `get_chart`, `get_statistics`, `summary`, etc. Why it matters: this is a direct usability failure for first-time users. Cleanest minimal fix: rewrite all examples against the current `AnalysisResult` API and test them in CI.

10. `P1` `get_statistics()` has an unstable contract for stratified results. The docstring promises a flat dict of chart stats in [`analysis_result.py:586-609`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L586), but stratified runtime returns a dict keyed by stratum. Why it matters: consumers cannot type or rely on the method without branching on hidden structure. Cleanest minimal fix: document and type it explicitly, or add `get_statistics(chart, stratum=None)` so the public contract is stable.

11. `P1` The top-level namespace is too broad for a first release. [`processbehavior/__init__.py`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/__init__.py#L76) exports advanced and internal-leaning types like `Analysis`, `AnalysisDataSet`, `EffectsCalculator`, `SDSRegistry`, and theming utilities. Why it matters: every root export becomes part of your support burden and semver contract. Cleanest minimal fix: narrow root exports to the stable end-user surface: `ProcessBehavior`, `Study`, `AnalysisResult`, key exceptions, and a few intentionally supported helpers.

12. `P1` Importing `processbehavior` eagerly pulls plotting infrastructure and is expensive. [`__init__.py`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/__init__.py#L65) imports plotting at module import time; runtime import was about 492 ms in this environment and pulled the whole Plotly stack. Why it matters: CLI use, notebook startup, and server cold starts get heavier than they need to be. Cleanest minimal fix: lazily import plotting helpers on first use or move them behind submodule imports.

13. `P1` Public mutability leaks still exist through `.charts` and `iter_charts()`. `AnalysisResult` stores raw chart structures at [`analysis_result.py:153-158`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L153), and [`iter_charts()`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L760) yields the original objects, not copies. Why it matters: callers can accidentally corrupt later operations. Cleanest minimal fix: expose read-only wrappers or return copies consistently from `iter_charts()` and hide raw `.charts` behind an accessor.

14. `P1` Data cleaning is still very opinionated and happens silently in the constructor. [`ProcessBehavior.__init__`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/process_behavior.py#L340) rewrites domain tokens to `NA` and can coerce formatted strings to numeric. Why it matters: silent coercion is convenient until it destroys meaning in regulated or production settings. Cleanest minimal fix: add a `cleaning="convenience" | "strict"` switch, with strict mode defaulting to no coercion beyond explicit `na_values`.

15. `P1` The documented default NA policy does not match the actual implementation. Compare [`docs/reference/api.md:14-18`](/Users/nicholas/Documents/projects/processbehavior/docs/reference/api.md#L14) with the actual defaults in [`process_behavior.py:362-375`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/process_behavior.py#L362). Why it matters: data cleaning behavior is part of your core contract. Cleanest minimal fix: generate docs from code or at minimum synchronize the documented token list with the implementation.

16. `P1` `read_parquet()` is public but its engine requirement is implicit. [`ProcessBehavior.read_parquet()`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/process_behavior.py#L513) is documented as first-class, but `pyarrow` is only in `dev` extras in [`pyproject.toml:23-34`](/Users/nicholas/Documents/projects/processbehavior/pyproject.toml#L23). Why it matters: users can discover a public API they cannot use after normal installation. Cleanest minimal fix: either add a `parquet` extra and document it, or clearly mark `read_parquet()` as requiring an external engine.

17. `P2` Strata typing is still wrong for multi-key stratification. Docs and annotations say `list[str]` in [`analysis_result.py:371-383`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L371), but runtime can produce tuples, and the code explicitly does that in [`analysis.py:2397-2399`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis.py#L2397). Why it matters: typed consumers and docs users will write the wrong code. Cleanest minimal fix: change the contract to `list[str | tuple]` or introduce a dedicated `StratumKey` type alias and use it everywhere.

18. `P2` `get_stratified_chart()` uses substring matching instead of canonical identity. The implementation at [`analysis_result.py:707-728`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L707) searches chart names containing the supplied text. Why it matters: partial matches are ambiguous and unsafe. Cleanest minimal fix: make it accept only exact values from `result.strata` and internally delegate to `focus(stratum).get_chart(...)`.

19. `P2` `get_stratified_charts()` assumes a chart-per-stratum storage model that the runtime no longer uses. See [`analysis_result.py:670-678`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L670) versus actual chart construction in [`analysis.py:994-1008`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis.py#L994). Why it matters: this helper cannot be trusted. Cleanest minimal fix: have it materialize `{stratum: focused_result_or_dataframe}` from the combined chart plus `strata`.

20. `P2` `list_strata()` reconstructs values by parsing chart names, not by reading canonical metadata. The logic in [`analysis_result.py:748-758`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L748) is now incompatible with the actual combined-chart structure. Why it matters: it will drift again. Cleanest minimal fix: return `self.strata` directly.

21. `P2` `FocusedAnalysisResult.focus()` regresses to raw `ValueError`. See [`analysis_result.py:1615-1620`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/analysis_result.py#L1615). Why it matters: this breaks the otherwise improved exception story exactly where users will chain drill-down operations. Cleanest minimal fix: raise `ValidationError` with the same message.

22. `P2` The docs still present Plotly and OpenPyXL as optional even though they are core dependencies. [`docs/getting-started/installation.md:7-15`](/Users/nicholas/Documents/projects/processbehavior/docs/getting-started/installation.md#L7) says they are optional, but [`pyproject.toml:14-19`](/Users/nicholas/Documents/projects/processbehavior/pyproject.toml#L14) installs them for everyone. 23. `P2` The tracked codebase is not lint-clean. `ruff` flags an unused variable in [`processbehavior/plotting/plotter.py:437`](/Users/nicholas/Documents/projects/processbehavior/processbehavior/plotting/plotter.py#L437). Why it matters: you want a clean release branch and reproducible CI. Cleanest minimal fix: remove the dead assignment and keep `ruff check .` green before tagging.

24. `P3` Release hygiene is messy because the repo root has untracked generated artifacts and helper outputs. `git ls-files --others --exclude-standard` currently shows HTML reports, simulation outputs, and doc helpers in the root and `simulation/`. Why it matters: it increases the chance of accidental inclusion and makes release review noisier. Cleanest minimal fix: add or expand `.gitignore`, move generated files under a dedicated ignored directory, and cut the tag from a clean tree.

25. `P4` Type-checking policy is still permissive enough to hide real future regressions. [`pyproject.toml:53-83`](/Users/nicholas/Documents/projects/processbehavior/pyproject.toml#L53) disables many mypy error classes across the package. Why it matters: not a release blocker, but it weakens your ability to keep the API stable as you iterate post-1.0. Cleanest minimal fix: keep current global config for now, but start re-enabling checks module-by-module on the public surface first.
